# Visual Provider Keys and Reference Inputs — Implementation Plan

## 1. Pruna key foundation

Files: `src/lib/client-pruna-key.ts`, `src/lib/pruna-key-validation.ts`, `src/lib/resolve-pruna-key.ts`, associated tests.

Add local storage/header helpers, conservative validation, and server resolution with request-key-over-environment priority. Write failing tests first for storage, headers, validation, precedence, and non-leakage.

## 2. Provider availability and sidebar

Files: `src/hooks/usePrunaKey.ts`, `src/hooks/useProviderMode.ts`, `src/components/sidebar/PrunaAccountSidebarSection.tsx`, `src/components/sidebar/PersonalizationSidebarSection.tsx`, `src/components/layout/AppSidebar.tsx`, `src/app/api/capabilities/route.ts`, tests.

Enable Pruna when either a local key or server fallback exists. Add masked connect/disconnect controls. Reset an invalid Pruna selection when neither source remains. Keep Pollen and Pruna entitlements independent.

## 3. Internal request and Pruna-only output

Files: `src/lib/services/chat-service.ts`, `src/app/api/generate/route.ts`, `src/lib/pruna/client.ts`, tests.

Send `X-Pruna-Key` only to the internal generate endpoint, resolve it server-side, and pass it explicitly into Pruna calls. If Pollinations media storage is unavailable, return the generated bytes and teach the client to consume a media response as a blob URL.

## 4. Registry and provider payloads

Files: `src/config/unified-image-models.ts`, `src/config/pruna-models.ts`, `src/lib/pruna/client.ts`, model/client tests.

Correct reference maxima and frame capabilities. Add/retain the intended Ideogram variants. Correct P-Image Edit, Try-On, P-Video, P-Video Replace, and VACE field mappings according to their API documentation.

## 5. Semantic video frame UI

Files: `src/hooks/useUnifiedImageToolState.ts`, `src/components/chat/input/VisualizeReferenceBadges.tsx`, input/container components, `src/components/page/ChatInterface.tsx`, send coordinator/types, tests.

Represent start and end frames separately for video, render model-aware upload fields, preserve image-model multi-reference behavior, serialize frames in the required order, and clear an end frame when switching to a start-only model.

## 6. Server validation

Files: `src/app/api/generate/route.ts`, registry helpers, route tests.

Reject excessive references, missing required semantic inputs, and end frames on unsupported video models before any provider call.

## 7. Verification

Run focused tests after each red/green cycle, followed by typecheck, lint, full Jest suite, and `git diff --check`. Browser verification remains with the user, per project instruction.
